# Кабинет группы ПОНБ-УП-304С

Неофициальный учебный сайт студентов специальности «Правовое обеспечение национальной безопасности». React + TypeScript + Vite, статическая сборка, без регистрации, сервера, платных API и обязательных внешних шрифтов.

> **Эта реализация сохранена в ветке [`verified-cabinet`](https://github.com/luwili/ponb-up-304s-cabinet/tree/verified-cabinet).** По выбору владельца в `main` оставлена параллельная другая реализация (коммит `1c91c5d`). Публичный сайт развёртывается из `main`, поэтому его текущие функции и данные могут отличаться от описанных здесь. Тесты и инструкция ниже относятся именно к этой ветке. Ветка не подменяет выбранную владельцем основную версию.

## Быстрый запуск

Нужен **Node.js 24 LTS**. Откройте терминал в папке проекта:

```bash
npm ci
npm run dev
```

Адрес появится в терминале (обычно `http://localhost:5173`). Сборка: `npm run build`. Просмотр готовой сборки: `npm run preview`. **Локальный адрес не делает сайт доступным всему интернету.** Для этого нужна публикация ниже.

## Что уже работает

- Главная с быстрыми переходами, сегодняшними парами, сроками, объявлениями и новыми материалами; честные пустые состояния.

- Задачи с условием, вопросами, скрываемым решением, краткой записью и исходными нормативными источниками.
- Расписание по дням/неделям, конкретные даты, повторяющиеся пары, учебная чётность, исключения.
- Задания с фильтрами и личными отметками; экзаменационные карточки, перемешивание, «Повторить»/«Знаю».
- Русскоязычный поиск по материалам, их тексту и метаданным, предметам, темам, преподавателям и кафедрам. «е»/«ё» и регистр равнозначны.
- 8 кафедр и **182 записи преподавателей** из действующих карточек официального сайта; поиск, фильтры, профили, источники и даты получения. Человек может иметь несколько записей на разных кафедрах.
- Пустая группа по умолчанию; отдельный безопасный импорт CSV/JSON с явным разрешением публикации.
- Светлая/тёмная темы, мобильное меню, клавиатура, фокус, уменьшение анимации.

## Публикация и GitHub Pages

Репозиторий: **https://github.com/luwili/ponb-up-304s-cabinet**. Эта версия: **https://github.com/luwili/ponb-up-304s-cabinet/tree/verified-cabinet**. Адрес Pages основной версии: **https://luwili.github.io/ponb-up-304s-cabinet/**. Состояние публикации и проверки: [Actions](https://github.com/luwili/ponb-up-304s-cabinet/actions) и `VERIFICATION.md`.

По официальной документации, проверенной 22.10.2026, Pages размещает статические HTML/CSS/JS. GitHub Free поддерживает Pages из публичного репозитория. Код и включённые материалы в таком репозитории будут общедоступными. Не загружайте чужие персональные данные, секреты или материалы без права распространения.

Если вы настраиваете публикацию на другом компьютере, установите [GitHub CLI](https://cli.github.com/) и выполните:

```bash
gh auth login
```

Выберите авторизацию через браузер. **Не передавайте токен в чат.** Существующий проект пересоздавать не нужно.

Для нового независимого размещения после авторизации (не выполняйте создание повторно для существующего проекта):

```bash
gh repo create ponb-up-304s-cabinet --public --source=. --remote=origin --push
gh api --method POST repos/{owner}/{repo}/pages -f build_type=workflow
gh workflow run deploy.yml
gh run list --workflow deploy.yml
```

Если репозиторий уже есть, **не создавайте дубль и не меняйте remote**. Включить публикацию можно также через Settings → Pages → Source → GitHub Actions. Для существующего приватного репозитория сначала проверьте тариф; не меняйте видимость автоматически.

Workflow `.github/workflows/deploy.yml` устанавливает зависимости по lock-файлу, проверяет публичный каталог, типы и тесты, собирает сайт, запускает браузерные тесты и публикует **только `dist/`**. Доступ к исходной локальной папке runner не нужен. Сетевое обновление справочника не выполняется при сборке.

Посмотреть результат: вкладка **Actions** → `Publish study cabinet`. URL размещения показывается у job `deploy` и в Settings → Pages. При переносе шаблон адреса — `https://<владелец>.github.io/<репозиторий>/`.

Маршруты вида `#/teachers` работают при прямом открытии и обновлении. Vite использует относительную базу `./`: ресурсы работают и в корне, и в подпапке с **любым реальным именем репозитория**. Если нужно, базу можно явно задать переменной `BASE_PATH=/имя-репозитория/` при сборке.

Официальные источники: [о Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages), [тарифы](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [Actions для Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Где настраивается группа

`content/group.config.json`: точное имя `ПОНБ-УП-304С`, специальность, `Asia/Yekaterinburg`, необязательные `course`, `semester`, `studyForm`. Курс и форму обучения мы не выводим из номера группы. Институт, Уфа, контакты и внешние ссылки — `src/data/institute.json`.

Все календарные даты обрабатываются в Уфе, независимо от часового пояса устройства. Для даты без времени не показывается ложный точный дедлайн.

## Как подключить материалы

Выбирайте **отдельную папку с разрешённым публичным контентом**, не домашнюю папку и не весь рабочий каталог. Импорт не изменяет оригиналы.

Linux/macOS:

```bash
CONTENT_PATH="/абсолютный/путь/Материалы группы" npm run content:import
npm run build
```

PowerShell:

```powershell
$env:CONTENT_PATH = "C:\Материалы группы"
npm run content:import
npm run build
Remove-Item Env:CONTENT_PATH
```

Или `npm run content:import -- "/путь с пробелами"`. Без пути импортируется **только `content/` проекта**, а не случайные папки. Без материалов он создаёт пустой рабочий каталог.

Рекомендуемая структура:

```text
materials/
  group.config.json
  subjects.json
  schedule.json
  assignments.json
  announcements.json
  exam-questions.json
  mapping.json
  subjects/
    subject-id/
      topic-id/
        topic.meta.json
        full.md
        short.md
        attachments/
```

Пустые конфигурации находятся в `content/`, шаблон темы и пустые шаблоны списка — в `examples/`. Демонстрационные материалы — **только** в `tests/fixtures/materials/`, в обычный сайт они не попадают.

### Предмет, тема и варианты конспекта

`subjects.json`:

```json
[{"id":"subject-id","title":"Название предмета","teacherIds":[]}]
```

`subjects/subject-id/topic-id/topic.meta.json`:

```json
{
  "id":"topic-id",
  "title":"Название темы",
  "subjectId":"subject-id",
  "materials":[
    {"file":"full.md","material":{"id":"note-full","title":"Полный конспект","type":"Конспект","variant":"full"}},
    {"file":"short.md","material":{"id":"note-short","title":"Кратко для записи","type":"Конспект","variant":"short"}}
  ]
}
```

Материалы в папке темы и вложенных папках прикрепляются к ней. Их названия и типы можно уточнить в `materials`. При отсутствии метаданных идентификатор стабилен относительно пути; при явном `id` можно переносить файл без смены идентификатора. Названия `full.md`/`short.md` сами по себе **не** доказывают связь вариантов.

Для произвольной существующей структуры используйте `mapping.json` — не обязательно переименовывать файлы:

```json
[{"file":"Лекции/Тема 1.md","subjectId":"subject-id","topicId":"topic-id","topicTitle":"Название темы","material":{"id":"note-1","title":"Лекция 1","type":"Конспект"}}]
```

Без надёжного сопоставления файл попадает в «Не распределено» с предупреждением отчёта. Указанный, но отсутствующий файл — критическая ошибка.

Типы: `Конспект`, `Задача`, `Презентация`, `Учебный материал`, `Вопросы к экзамену`, `Судебная практика`, `Другое`. Для задачи можно задать `material.task` с `condition`, `questions`, `solution`, `shortSolution`, `sources`. Без этих полей показывается оригинальный материал, решение не сочиняется.

Для материала также поддержаны `description`, `tags`, `addedAt`, `updatedAt`, `order`, `relatedIds`, `sourceUrl`, `verifiedAt`, `verificationNote`, `alt`. Даты — `YYYY-MM-DD`. Даты файлов не подменяют юридическую проверку. Источники, решения и исходный текст не переписываются импортом.

### Расписание, задания, объявления, экзамены

- `schedule.json`: `{"lessons":[],"exceptions":[]}`. Пара: `id`, `subjectId`, `start`/`end` (`HH:MM`), **либо** `date`, **либо** `weekday` (1 — понедельник, 7 — воскресенье); необязательные `parity` (`all`, `odd`, `even`), `kind`, `room`, `url`, `teacherId`, `note`.
- Повторение действует только в пределах `semesterStart`/`semesterEnd` из `group.config.json`. `referenceWeek` — любая дата **первой (нечётной) опорной учебной недели**, а не календарный номер недели. Без необходимых параметров повторяющиеся пары не угадываются.
- Исключение: `{"date":"2026-11-02","lessons":[]}` отменяет весь шаблон дня. Для переноса укажите в `lessons` новые пары с `date`. Исключения заменяют и конкретные, и повторяющиеся занятия этого дня.
- `assignments.json`: массив `{id,title,subjectId,description,dueDate?,dueTime?,materialIds:[]}`. Время задаётся только при известной дате и считается временем Уфы.
- `announcements.json`: массив `{id,title,body,publishedAt,expiresAt?,pinned:false}`. Будущие и истёкшие объявления не выводятся на главной, дата окончания включительно.
- `exam-questions.json`: массив `{id,title,subjectId,answer?,materialIds:[]}`. Ответ только из явно подготовленных данных.

Связи с преподавателями задаются полными `teacherIds` у предмета, `teacherId` у пары либо `groupTeacherIds` у группы. Идентификаторы берите из справочника; по фамилиям/инициалам люди автоматически не объединяются.

### Отчёт и безопасность импорта

`reports/content-import.json`: добавлено, обновлено, удалено, пропущено, предупреждения и ошибки. Полные локальные пути не записываются в публичные ссылки. При критической ошибке старый каталог остаётся целым. Повторный запуск не создаёт дубли; удалённые файлы исчезают из результата, а не из оригиналов.

Разрешены MD, TXT, PDF, DOC/DOCX, PPT/PPTX, XLS/XLSX, ODT/ODS/ODP, PNG/JPG/JPEG/WEBP/GIF. HTML, JS, SVG, архивы, исполняемые файлы, `.env`, скрытые/временные файлы и символические ссылки не копируются. Каталоги `private-data` и файлы с именем `roster`/`список группы` пропускаются. Нельзя указывать абсолютные/выходящие за папку пути в сопоставлении. Markdown/TXT должны быть UTF-8.

**Проверяйте сами, что файлы разрешено публиковать**: импортёр не распознаёт ФИО или секреты внутри произвольно названного конспекта. Он не является системой юридической экспертизы или антивирусом. DOCX/PPTX/XLSX и аналогичные форматы доступны как оригиналы, без обещания онлайн-редактирования. Поиск PDF/Office ограничен метаданными; OCR и извлечение текста не реализованы. Изображения из Markdown не загружаются с внешних сайтов: прикрепите их как отдельные файлы для просмотра.

## Список группы — отдельно и приватно

По умолчанию **`publishRoster:false`**. Исходный список храните вне репозитория либо в исключённой `private-data/`. `ROSTER_PATH` не читается вообще, пока публикация выключена. В каталоге и поиске ФИО не будет.

Для осознанно разрешённой **публичной** публикации: включите `publishRoster:true` и отдельно укажите `ROSTER_PATH`. Передача файла сама по себе не является разрешением.

```bash
CONTENT_PATH="/публичные материалы" ROSTER_PATH="/приватная папка/roster.json" npm run content:import
```

```powershell
$env:CONTENT_PATH = "C:\Публичные материалы"
$env:ROSTER_PATH = "C:\Приватная папка\roster.csv"
npm run content:import
```

JSON: массив объектов `id`, `name` (ФИО), необязательные `role` и `order`. CSV: UTF-8, разделитель — запятая, заголовок `id,name,role,order`, кавычки по правилам CSV. Телефоны, почта, адреса, оценки и даты рождения не нужны и не поддерживаются. Шаблоны пустые. В интерфейсе — поиск и алфавитная сортировка.

Если нужен доступ **только одногруппникам**, необходим отдельный сервер с настоящей авторизацией и защищённым хранилищем. Скрытая ссылка/пароль в JavaScript не защищают данные на Pages.

Файлы `Список группы.md` и `Расписание на 19-25 ноября.png`, находившиеся в рабочей папке до разработки, не читались и не импортировались. Они исключены из Git; их содержание и принадлежность семестру не предполагаются.

## Справочник института

```bash
npm run institute:sync
```

Команда последовательно запрашивает `https://law-bsu.ru/kafedry`, восемь страниц кафедр и `https://law-bsu.ru/contacts`, берёт только текущие карточки состава, краткие научные интересы и подтверждённые ссылки сервисов. Исторические упоминания не включаются; фотографии не используются. Степень и звание разделяются по полю «Учёная степень/звание», должность читается отдельно.

Результат: `src/data/institute.json`, отчёт: `reports/institute-sync.json`. Каждая запись имеет `sourceUrl`/`retrievedAt`. При сбое отдельной страницы сохраняется предыдущая версия этой кафедры; полный провал не обнуляет файл. После обновления проверьте изменения и отчёт перед коммитом. Обычная сборка **не обращается** к сайту института.

Краткие описания кафедр — из официального каталога. Адрес и служебные контакты — только с `/contacts`. Профили справочника не означают, что сотрудник ведёт занятия у нашей группы. Последнее успешное получение: **22.10.2026, 182 записи, 8 кафедр, 0 предупреждений**. Иные собственные `teachers.json`/`departments.json` в учебной папке не применяются: справочник обновляется отдельной проверяемой командой, а не произвольными учебными файлами.

## Два способа обновить публичный сайт

**1. Публичные исходники в репозитории.** Добавьте разрешённые материалы в `content/`, создайте пустой файл `content/import-on-deploy`, проверьте локальный импорт и закоммитьте. Workflow пересоберёт каталог из `content/`. Приватный список этим способом не подключайте.

**2. Импорт с локального диска.** Оставьте `content/import-on-deploy` отсутствующим. Запустите импорт с `CONTENT_PATH`, проверьте `public/generated/` и отчёт, затем закоммитьте **подготовленный** каталог и файлы. Workflow валидирует их и не перезаписывает пустым локальным шаблоном.

```bash
npm run content:prepare
npm run check
npm run build
git status
git add public/generated content src
git diff --cached --stat
git commit -m "Обновить публичные учебные материалы"
git push
```

После push в `main` Actions публикует обновление. Статический сайт **не читает `CONTENT_PATH` на вашем компьютере**: без импорта/сборки/push у остальных пользователей ничего не изменится.

Не выполняйте `git add .` для случайной папки с личными файлами. Перед коммитом проверяйте `git diff --cached`, а перед публикацией — `dist/`. Избранное и отметки не входят в общие данные, не являются резервной копией и не синхронизируются между устройствами.

## Проверки и структура

```bash
npm run check       # TypeScript + сценарные тесты импорта/расписания
npm run build
npx playwright install chromium
npm run test:e2e    # Chromium: 360, 768, 1440 px, подпапка хостинга
npm run schemas    # JSON Schema из валидируемых Zod-схем
```

`src/lib/schema.ts` — модели и runtime-валидация; `schemas/` — JSON Schema. `src/pages/` — учебные разделы, планировщик и сообщество; `src/styles.css` — адаптивный дизайн; `scripts/` — импорт/синхронизация; `public/generated/` — единственный подготовленный публичный контент; `tests/` — изолированные тестовые примеры. Тесты запускают временный сайт в `/tmp/opencode/`, не заменяя рабочий каталог.

См. `VERIFICATION.md` для результатов проверок. Линтер отдельно не настроен: обязательная статическая проверка — строгий TypeScript.

## Резервная копия и ограничения

- Репозиторий хранит код и публичные данные. Отдельно копируйте исходные материалы и приватную папку на свой резервный носитель. Не кладите приватные копии в публичный репозиторий.
- `node_modules/`, `dist/`, `.env*`, `private-data/`, `reports/`, браузерные артефакты и исходные локальные файлы группы исключены из Git. `dist/` всё же публичен **при развёртывании**, поэтому проверяйте его состав.
- Личные браузерные данные могут исчезнуть при очистке хранилища. Сайт обрабатывает его отказ/повреждение без падения.
- Нет аккаунтов, общей панели редактирования, закрытого доступа, OCR, юридической проверки текста и автоматических ответов. Общий контент меняется только через сборку. Доступность и сведения внешних сайтов могут изменяться.
- Для отправки последующих изменений нужен авторизованный GitHub; успешный локальный тест сам по себе не является успешным запуском GitHub Actions.
